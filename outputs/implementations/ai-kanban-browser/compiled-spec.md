# AI Kanban — Browser Workspace for Human-AI Work

## 1. Architecture and Board Workspace lifecycle

Build a polished static JavaScript application for GitHub Pages with no backend, server routes, serverless functions, Node.js runtime requirement, cloud coordination service, or mutable CDN dependency. Deliver it under `outputs/implementations/ai-kanban-browser/`. Use semantic HTML, modern CSS, standards-based ES modules, relative asset URLs, and locally vendored pinned dependencies. The root must contain `index.html` and work from a GitHub Pages repository subpath. Use Web Workers for database, search, parsing, and other CPU-heavy work. Keep domain state behind repository/service interfaces; UI code must not issue raw storage queries.

AI Kanban is a portable, local Board Workspace in which cards are durable human–AI workspaces. A workspace folder contains `board.sqlite`, a versioned manifest, attachments, artifacts, exports, and private coordination files. The useful board workflow must work without an AI provider. It must support organization, planning, activity preservation, typed outputs, research memory, and versioned AI handoff packets.

First run must offer Open Board Workspace, Create Board Workspace, and Try demo. Try demo must visibly distinguish Create a real demo workspace, which uses normal folder validation, bootstrap installation, and Personal Research seed data, from Try in memory, which creates no folder, disables local-agent integration, and requires export to retain work. When folder access is unavailable, explain why only the in-memory path works. Open, Create, demo activation, reconnect, and import are single-flight: disable competing entry actions until the active operation completes.

Use `showDirectoryPicker()` only from an explicit user gesture in a secure context. Request permission from a gesture, persist a recent `FileSystemDirectoryHandle` only in IndexedDB for reconnection, and query permission before requesting again. Before an operation replaces dirty state, require save success or explicit confirmation; cancellation keeps the active workspace unchanged. Show folder name, permission mode, dirty/saving/saved/conflict state, and last durable write. Close clears in-memory state and offers portable export.

The selected folder is the trust, portability, and collaboration boundary. Define a manifest with `workspace_id`, format and bootstrap protocol versions, `board.sqlite`, reserved directories, managed paths, and fingerprints. Use documented relative paths only; reject absolute paths, `..`, symlink escapes, malformed paths, and paths outside the workspace. Do not alter unrecognized files. Require confirmation for destructive cleanup of recognized application-owned files. Treat all workspace content as untrusted data.

Serialize browser writes with one save queue; coalesce edits without dropping the final state and let explicit Save flush pending work. Compare on-disk revision and content fingerprint before replacement. Abort into reload or explicit conflict recovery on unexpected changes; never silently overwrite. Retain previous bytes until replacement closes successfully. Coordinate tabs with Web Locks and `BroadcastChannel`; a second tab is read-only unless it obtains the workspace lock. Support connected-folder autosave on compatible Chromium browsers and an honest workspace archive import/download fallback elsewhere.

## 2. SQLite schema and repository operations

Use a pinned, locally hosted SQLite WASM distribution in a dedicated Worker. The Worker owns the sole live connection, imports database bytes from `Uint8Array`, exports complete database bytes, validates all messages, and exposes create, open, snapshot/query, mutation, export, close, and health operations. `board.sqlite` is canonical; memory, OPFS, IndexedDB, and caches are working state only. Do not concatenate user content into SQL. Enable foreign keys, rollback-journal mode, full synchronous durability, bounded busy timeout, deterministic transactional migrations, and a metadata table for schema version. Preserve original bytes before migration and reject unsupported future versions.

Use stable text IDs, integer ordering keys, UTC ISO 8601 timestamps with timezone offsets, explicit field types, defaults, constraints, and indexes. Define tables and indexes for workspace metadata and revisions; boards and columns; cards; plan items; immutable execution turns; turn checkpoints; questions and answers; output surfaces and versions; append-only activity; research-memory and source-coverage records; dependencies; agent records; grants/control generations; and coordination outbox/idempotency records.

Cards must contain title, Markdown description, priority `P0`–`P3`, assignee, created/updated/archived timestamps, kind `task`, `question`, or `result`, attention state, workflow projection, last-change actor, dependencies, relative artifact paths, provenance, and ordering/search fields. Default ordered columns are Inbox, Planning, In Progress, Review, Blocked, and Done. Provide create, edit, archive, search, filter, reorder, move, and detail projections. Moving or reordering plus its activity event is one SQLite transaction. Completing or failing a turn, updating its card projection/workflow position, and appending final activity must also be transactional.

Return updated snapshots or precise change records from every mutation and mark the external file dirty. Surface typed, actionable errors for corruption, migration rejection, lock/busy state, stale revision, permission loss, invalid manifest, malformed import, export failure, and Worker failure. Document and enforce a practical workspace-size limit while preserving responsiveness.

## 3. Human-agent coordination and skill protocol

Install `AGENTS.md`, `CLAUDE.md`, and the canonical `.agents/skills/ai-kanban/` bundle in every created workspace. The bundle contains `SKILL.md`, a dependency-free Python 3 CLI, and thin POSIX-shell and PowerShell launchers. Root instruction files point to the canonical skill and do not duplicate its protocol. Record generated files, protocol version, and fingerprints in the manifest. On reopen, verify the bundle and offer Repair or Update when missing, outdated, or inconsistent. Never silently overwrite user-created or edited instructions, skills, or launchers; show a comparison and require approval.

The Python skill uses only standard-library facilities including `sqlite3`, `argparse`, JSON, and filesystem APIs. It preflights Python and required modules. If runtime installation is needed, show the exact trusted command and require approval; never install silently or elevate privileges. After create or reopen, tell the user to start Copilot CLI, Claude Code, or a compatible agent in the workspace. Do not fabricate an absolute path or `cd` command from a directory handle. Show Waiting for agent until a valid workspace-matched heartbeat arrives, then show identity, durable control holder, current turn, and last heartbeat. Provide fallback instructions, diagnostics, repair, and retry if no heartbeat arrives.

Reserve a private coordination directory with a versioned human signal and one versioned state file per approved agent. Each actor writes only its own state file. Records include `workspace_id`, protocol version, actor or holder ID, monotonic sequence or `control_generation`, timestamp, requested state, and observed durable revision. Replace files safely and ignore incomplete, stale, mismatched-workspace, and lower-generation records. Keep substantive questions, answers, progress, outputs, and audit history in SQLite; mailbox files are signals and commit markers, not a second domain database.

Model control as `human`, `granting_agent`, `agent`, `reclaim_requested`, and `recovering`, with owner, `holder_id`, `control_generation`, `workspace_revision`, and bounded lease metadata. Every mutation verifies the expected generation, holder, actor, run ID, and revision immediately before writing. Control transfer requires request and acknowledgement: the current owner commits or rolls back, closes its writer, publishes final revision, and acknowledges before another writer proceeds. Human reclaim has priority. A stale lease is recovery evidence, never permission to overwrite.

Because browser whole-file replacement does not use native SQLite advisory locks, the control protocol is authoritative. Store generation and revision in SQLite and coordination records. Before browser grant, flush saves, increment generation, grant the selected actor in SQLite, close the writable stream, publish the grant, and enter read-only mode. Before each agent mutation, read the latest signal, open a fresh connection, use `BEGIN IMMEDIATE`, verify control and revision, apply mutation and audit event, increment revision, commit, close, and publish the revision. Never retain a transaction through reasoning, tools, artifact generation, waiting, or polling. After an agent commit, wait for journal disappearance, validate integrity, confirm the announced revision, then reload.

The CLI must inspect status, read ready work, atomically claim/release turns, apply typed mutations, publish artifact references, ask structured questions, accept human answers, grant/regrant/resume/yield, and watch. Mutations require expected revision, generation, actor, run ID, and idempotency key. Concurrent changes fail fast with typed busy/conflict results and require fresh preflight. Publication failures are typed; retrying with the same idempotency key republishes the durable outbox. Freeze and revalidate the user-confirmed grant target after pending saves and before transfer. Display the durable SQLite holder rather than an unrelated newer heartbeat.

Watch mode is opt-in and uses bounded polling, quiet backoff, resumable cursor, heartbeat, clean cancellation, and machine-readable events. It atomically claims work, persists cursor/idempotency state, yields on reclaim, never busy-waits, and never holds transactions between polls. Generated instructions require the loop poll, claim, work, checkpoint, ask or complete and yield, then resume watching while the host remains alive. State plainly that a skill cannot force a terminated host runtime to act. For stale control, offer a copyable guarded recovery command bound to revision/generation only after the user confirms the old process stopped; cancel interrupted active turns before yielding and preserve partial work.

## 4. Cards, decision loops, execution turns, memory, and output surfaces

Cards are mixed operational, informational, and navigational units. They must be scannable at rest and expose richer detail in a panel or detail view. Support pointer and keyboard controls, visible focus, drag previews/drop targets, keyboard movement, cancellation, accessible context actions, and clear reasons for blocked transitions.

An execution turn is one bounded immutable attempt for durable card intent. Each turn has stable ID, parent card ID, monotonic display number, status `queued`, `claimed`, `running`, `needs_input`, `review`, `complete`, `failed`, or `cancelled`, trigger/requester, actor, run ID, idempotency key, instruction/card-revision snapshot, timestamps, plan/checkpoints, summary/error, output IDs, and memory lineage. At most one active turn exists per card by default. Initial placement exposes Ready for agent. Claim queued turns atomically.

Run again/Requeue creates a fresh queued turn with a new ID and number, links the prior successful turn, snapshots current instructions, and preserves every prior turn. It must not reopen or clear completed work. Moving completed work to Inbox confirms Run again and performs this requeue operation. A turn needing input resumes after answer; cancellation retains partial outputs, activity, and reason. Append activity for queue, claim, start, checkpoint, question, answer, output, completion, failure, cancellation, and requeue.

Implement a durable decision thread with `briefing`, `exploring`, `needs_feedback`, `committed`, `deep_work`, `review`, and `accepted` phases independent of board columns. The briefing stores goals, candidates, constraints, preferences, exclusions, budget/effort bounds, criteria, and unknowns. Exploration produces bounded structured comparisons covering criteria fit, evidence, tradeoffs, uncertainty, practical constraints, and differentiators. Ask focused questions and yield at `needs_feedback` rather than guessing consequential preferences. Preserve proposals, feedback, questions, answers, rankings, selections, gates, artifacts, actors, timestamps, turns, and provenance append-only.

For the vacation flow, the human edits destinations and constraints in Inbox; Planning performs broad comparison and feedback; a confirmed move to In Progress is the explicit commitment gate and queues deep research with dated itineraries; Review offers revision or acceptance. Deep work snapshots selected option, constraints, unresolved questions, evidence, and feedback and does not reconsider rejected options without invalidating evidence. Changing the selection requires cancellation/replacement and another recorded gate.

Use typed versioned output surfaces with stable ID, owner, type, title, payload/reference, schema version, status, source, timestamps, lineage, and actions. Support text, status, link, program, table, diff, image, file, and form/question surfaces. Safely render Markdown; provide appropriate program, table, diff, image, file, approval, comparison, pin, minimization, and audit interactions. Every output belongs to a turn, carries version/status/actor/provenance and optional relative artifact path, and remains available in dated history. Feature the latest successful result with a rich preview.

Maintain recurring-topic memory with dated cycles, cadence, lookback, topic, mode, coverage, and gaps. Memory records fingerprint, normalized subject, summary, URL/publisher, evidence date, first/last seen, hash, relevance, and `current`, `updated`, `superseded`, `dismissed`, or `uncertain` state. Read previous reports and scoped memory; classify findings as new, materially updated, unchanged context, duplicate, corrected, or no longer current. Update only from committed source-backed results and preserve lineage. Let users inspect, correct, dismiss, pin, export, and explicitly forget memory without rewriting historical reports.

Activity is append-only with stable ID, semantic type, actor, target, timestamp, summary, structured payload, visibility, and correlation/trace ID. Persist before UI update. Render routine events compactly and significant events with expandable detail; distinguish human, AI, movement, output, decision, and error activity. Support relevant filters and avoid secrets or excessive raw internals.

## 5. Interface states and interactions

Create a calm, capable, trustworthy board rather than an operations console. Use restrained navy, mineral teal, warm paper, and coral attention accents. Use violet/teal for unreviewed AI changes and amber for Needs you, always with icon and text rather than color alone. Support reduced motion, semantic labels, native controls, strong visible focus, sufficient contrast, and responsive layouts down to 320 CSS pixels. The native `hidden` attribute is authoritative.

Before activation, show Open/Create. After activation, show Save, New card, Agent control, AI handoff, and Workspace menu. Foreground Needs you, AI working, and AI updated counts without global chat. Keep raw database information in About workspace. The board view includes column empty states, search, attention filters, state-aware actions, and save/control status. Card detail edits metadata and Markdown description; manages plans, outputs, turns, memory, activity, provenance, and dependencies; answers agent questions; supports Run again, archive, and publishing polished result cards. Preserve selection, scroll, opened detail, and unsaved form drafts across agent commits; flag edit conflicts rather than overwriting active input.

AI handoff exports a compact versioned JSON and Markdown packet for one selected item containing intent, context, plan, relevant activity, and requested response shape. Users may copy/download and then import a response packet by paste or file. Validate completely before preview and require approval of plan, outputs, status, and activity changes. Preserve packet and resulting activity as provenance. A replaceable `AIProviderAdapter` may exist, but provider credentials are session-memory only and never stored in localStorage, IndexedDB, logs, URLs, analytics, or workspace files. Before outbound transmission, show provider, endpoint, model, exact selected content, and purpose, and require confirmation. Network failure leaves workspace state unchanged and retains a retryable draft. Include a quiet footer linking source, compiled specification, and tutorial.

## 6. Security, compatibility, and recovery

Treat workspace files, imported archives, AI responses, external responses, attachments, artifacts, and generated content as untrusted. Safely render Markdown and structured data; never execute a file merely because it is in an authorized folder. Keep workspace bytes local unless an explicit feature shows exact outbound content and obtains confirmation. Do not upload workspace data for analytics, diagnostics, previews, or crash reporting. All external network calls require explicit user action and visible destination, purpose, progress, failure, and retry states.

Provide specific recovery for permission revocation, missing files, invalid manifest, corrupt database, unsupported future version, partial export, unsupported folder access, bootstrap inconsistency, external changes, read-only tabs, write conflicts, stale grants, incomplete coordination records, and integrity failure. Never silently fall back from a connected workspace to an unrelated OPFS database. Do not claim background execution, WebSockets, secure persistent secrets, multi-user coordination, or agent autonomy that static hosting cannot provide.
